3. 関数ごとの解説

このファイルの関数は main()(36-71 行)のみ。処理は 4 段からなる。

(1) 組成オブジェクト化(42-44 行): matminer の StrToComposition が formula_pretty 文字列を pymatgen の Composition に変換する。ignore_errors=True のため解釈不能な組成は例外ではなく NaN になり、後段の dropna で行ごと落ちる。

(2) Magpie 記述子(45-47 行): ElementProperty.from_preset("magpie")。組成に含まれる元素集合を $E$、元素 $e$ の原子分率を $x_e$($\sum_{e \in E} x_e = 1$)、元素物性(原子番号、融点、電気陰性度、価電子数、未充填軌道数など 22 種)の値を $p_e$ とすると、物性ごとに次の 6 統計量を出す:

$$\mathrm{mean} = \sum_{e \in E} x_e\, p_e,\qquad \mathrm{avg\_dev} = \sum_{e \in E} x_e\, |p_e - \mathrm{mean}|$$

$$\mathrm{min} = \min_{e \in E} p_e,\quad \mathrm{max} = \max_{e \in E} p_e,\quad \mathrm{range} = \mathrm{max} - \mathrm{min},\quad \mathrm{mode} = p_{e^*}\ (e^* = \arg\max_e x_e)$$

mean と avg_dev は分率加重、min/max/range は存在元素上の非加重統計、mode は最多分率元素の値である。$22 \times 6 = 132$ 列。列名は MagpieData mean NdUnfilled のような形式で、metrics.json の top10_features に現れる名前と一致する。

$$\hat y(x) = \frac{1}{B} \sum_{b=1}^{B} T_b(x)$$

$$\mathrm{MAE} = \frac{1}{n}\sum_{i}|y_i - \hat y_i|,\qquad \mathrm{RMSE} = \sqrt{\frac{1}{n}\sum_{i}(y_i - \hat y_i)^2},\qquad R^2 = 1 - \frac{\sum_i (y_i - \hat y_i)^2}{\sum_i (y_i - \bar y)^2}$$

($\bar y$ はテスト集合の平均)。交差検証は訓練側 12,383 行のみを 5 分割し(150-151 行、シャッフル無しの KFold)、fold ごとに新しいモデルを学習して $R^2$ の平均と標準偏差を報告する。テスト集合は CV に関与しない。

引数の影響: log_transform=True は σ の数桁のレンジを圧縮し、大きい値への二乗誤差の偏重を防ぐ。test_size を変えると n_train/n_test と全指標が変わる。SEED=42 固定により分割・木構造・CV が決定的で、metrics.json は再実行で同一値になる(入力 CSV が同一である限り)。計算量は木 1 本あたり $O(m \cdot n \log n)$($m=145$ 特徴量、$n$=訓練行数)で、それが $B \times (1 + 5)$ 回(本体 + CV)走る。実行時間は数分、fit が支配的。

shap_analysis(model, X_test, target, out_dir) -> pd.DataFrame(98-118 行)

テスト集合から最大 SHAP_SAMPLE_SIZE = 1000 行を抽出し、TreeExplainer で SHAP 値 $\phi_{ij}$(標本 $i$ における特徴量 $j$ の寄与)を厳密計算する。SHAP の加法性

$$\hat y(x_i) = \phi_0 + \sum_{j=1}^{145} \phi_{ij}$$

($\phi_0$ は学習データ平均に対応する基準値)により、予測値が特徴量ごとの寄与に分解される。重要度は標本平均絶対値 $I_j = \frac{1}{1000}\sum_i |\phi_{ij}|$ で(112-115 行)、降順ランキングを CSV 保存する。check_additivity=False は数値誤差チェックの無効化で値自体は変えない。

parity_plot(...)(73-95 行): 横軸に BoltzTraP 値、縦軸に予測値を等スケールで描き、対角線 $\hat y = y$ を参照線とする散布図。

main()(180-201 行): STAGE_CONFIG(48-67 行)からターゲット 2 つと変換フラグを取り、順に train_one_target を実行して metrics.json に書く。

4. なぜこの処理が必要か

物理側: 学習済みモデルは DFT+BoltzTraP という高コスト計算の代替(サロゲート)である。SHAP による band_gap_mp_eV の順位(S で 1 位、σ で 4/7 位)は、「バンドギャップが輸送物性を駆動する」という設計時の物理仮説をデータで定量化する役割を持つ。

機械学習側: ランダムフォレストはスケーリング不要・非線形・混合スケールの 145 特徴量をそのまま扱え、TreeExplainer による厳密 SHAP 計算と両立する。CV はテスト 1 回分割の偶然性を補い、平均 ± 標準偏差で汎化性能の安定性を示す。

5. この処理を外したらどうなるか

  • ファイルごと外す: モデル・metrics.json が生成されず、web/build_data.py:63 が metrics.json を読めず FileNotFoundError で停止。

  • CV を外す: 動作・保存物は metrics.json の cv_* 2 項目が欠けるだけだが、単一分割の R² のみとなり評価の信頼区間を失う。

価電子帯上端と伝導帯下端のエネルギー差 $E_g$ [eV]。$E_g > 0$ なら絶縁体・半導体、$E_g = 0$ なら金属。/ 特徴量 band_gap_mp_eV(featurize.py:28)として全モデルの入力になり、band_gap_mp_eV > 0 が半導体フィルタ(get_transport_data.py:171)。/ 本リポジトリには 3 種のバンドギャップが登場する: MP 登録値(band_gap_mp_eV、特徴量)、BoltzTraP 計算時の値(band_gap_boltztrap_eV、参考値で特徴量に不使用)、ステージ1 の band_gap_eV。混同しないこと。

直接遷移/間接遷移

価電子帯上端と伝導帯下端が運動量空間の同じ点にあれば直接、異なる点にあれば間接。/ is_gap_direct → is_gap_direct_int(featurize.py:50)として 0/1 特徴量。S_p モデルで SHAP 7 位。/ ギャップの「大きさ」($E_g$)とは独立な「型」の情報。

ゼーベック係数

温度勾配 $\nabla T$ が生む起電力の係数 $S$ [µV/K]。$\vec E = S \nabla T$。/ ステージ2 の目的変数 seebeck_p_uV_K・seebeck_n_uV_K(300 K、キャリア濃度 $10^{18}\,\mathrm{cm^{-3}}$、テンソル固有値平均)。/ 電気伝導率とは独立の量で、熱電性能指数 $ZT = S^2 \sigma T / \kappa$ では二乗で効く。

電気伝導率

電場 $\vec E$ に対する電流密度の応答 $\vec j = \sigma \vec E$ の係数 $\sigma$ [S/m]。/ ステージ3 の目的変数。データセットには $\sigma/\tau$ で収録され、$\tau = 10^{-14}$ s を掛けて S/m に換算(get_transport_data.py:45-47, 180-181)、学習は $\log_{10}\sigma$。/ 「抵抗率」はその逆数 $\rho = 1/\sigma$。本データの σ は実測値ではなく定緩和時間近似下の計算値である点が実験値との本質的な差。

定緩和時間近似

ボルツマン輸送方程式で、キャリアの散乱を単一の定数緩和時間 $\tau$(散乱間の平均時間)で表す近似。CRTA。/ Ricci データセットは $\tau = 10^{-14}$ s 固定で σ を計算(README:47-49)。σ の絶対値はこの仮定に比例して変わる。/ $S$ は CRTA の下では $\tau$ に依存しない(分子・分母で相殺)ため、S の値はこの仮定の影響を受けない。

BoltzTraP

DFT バンド構造からボルツマン輸送理論で $S$、$\sigma/\tau$ 等を計算するプログラム。/ 目的変数の生成元(Ricci et al. 2017 が MP のバンド構造に適用)。本パイプラインはこの計算の代替モデルを学習する。/ DFT はバンド構造を求める段、BoltzTraP はそこから輸送係数を求める後段で、別の計算である。

DFT

密度汎関数理論。電子密度を基本変数として多電子系の基底状態を計算する第一原理手法。/ MP 登録値(バンドギャップ、E_hull、密度等)の生成元であり、本パイプラインが「置き換える」対象の計算(README:5-7)。/ 経験パラメータを使う半経験的手法との対比で「第一原理」と呼ばれる。

GGA

一般化勾配近似。DFT の交換相関汎関数の一種。/ MP・Ricci データの計算水準(GGA/GGA+U)。バンドギャップを系統的に過小評価することが既知で、README:153-155 と index.html:194 が注意書きしている。/ より高精度な GW 近似やハイブリッド汎関数は高コストで、MP の大規模データには使われていない。

energy above hull

組成系の熱力学的凸包(その組成で最も安定な相・相分解の組み合わせ)からのエネルギー差 $E_{\mathrm{hull}}$ [eV/atom]。0 なら最安定。/ 安定相フィルタ $E_{\mathrm{hull}} \le 0.05$(get_data.py:63、get_transport_data.py:165-166)。ダッシュボードでは meV/atom 表示。/ 生成エネルギー(単体からの生成熱)とは異なる。生成エネルギーが負でも、より安定な競合相があれば $E_{\mathrm{hull}} > 0$ になる。

キャリア濃度

伝導に寄与する電子または正孔の密度 $n$ [cm⁻³]。/ データセット全体で $10^{18}\,\mathrm{cm^{-3}}$ に固定されており、列として存在しないため特徴量にならない(DATA_SOURCES.md:89-90)。/ ドーピング「濃度」はこの $n$ を指し、p 型/n 型という「極性」とは別の軸。

p型/n型

多数キャリアが正孔なら p 型、電子なら n 型。/ 全目的変数が p/n 別に収録され、モデルも 4 本に分かれる(seebeck_p_uV_K 等)。/ 同一材料に p と n の両方の値があるのは、同じバンド構造に対して両極性のドーピングを仮定して計算しているため。実試料の極性はドーパントで決まる。

結晶系

格子の対称性による 7 分類(立方・六方・三方・正方・斜方・単斜・三斜)。/ crystal_system を one-hot 化して 7 特徴量(featurize.py:53)、ダッシュボードのフィルタチップ(app.js:26-30)。/ 空間群(230 種)の粗い上位分類。

空間群

結晶の対称操作の群。1–230 の通し番号。/ spacegroup_number を整数のまま特徴量に使用(featurize.py:32)。S_p モデルで SHAP 4 位。/ 番号は分類ラベルであり、値の大小に連続的な物理量の意味はない(順序が対称性の高低と部分的に相関するのみ)。

多形

同一組成で原子配列が異なる結晶。/ ステージ1 で 8 組成が 114 行になる理由。ステージ2・3 でも 15,479 行中、組成の重複を持つ行が 4,666 行ある(92_audit.md)。/ 同素体は単体元素の場合の呼称。

有効質量

バンドの曲率で定義される、結晶中キャリアの見かけの質量 $m^*$。伝導度有効質量は $\sigma$ の計算に直結する。/ Ricci データに収録されているが、目的変数と同じ BoltzTraP 計算に由来するため特徴量から意図的に除外(featurize.py:8-9、README:70-73)。/ 自由電子質量 $m_e$ とは異なり、材料・バンドごとに変わる。

バイポーラ伝導

ギャップが小さい半導体で電子と正孔が同時に熱励起され、両者のゼーベック寄与(符号が逆)が相殺する現象。/ 「小さい $E_g$ が $|S|$ を急激に抑制する」という SHAP の方向性の物理的解釈(README:93-96)。/ 単一キャリア極性の伝導(通常のドープ半導体)との対比。

熱電材料

温度差から発電(またはその逆)する材料。性能は $S$、$\sigma$、熱伝導率 $\kappa$ で決まる。/ Bi₂Te₃、SnSe、Mg₂Si、ZrNiSn、CoSb₃ の残存確認(get_transport_data.py:188-197)がデータセットの健全性チェックになっている。/ パワーファクター $PF = S^2\sigma$ は Ricci データに収録されているが本リポジトリでは未使用。

Materials Project

DFT 計算物性の大規模公開データベース(略称 MP)。/ 特徴量とフィルタの供給源(summary API)。輸送物性は持たない(DATA_SOURCES.md:20-29 で全 69 フィールドを確認)。/ MPContribs とは別サービスである点に注意。

MPContribs

MP に付随するユーザー投稿データの基盤。/ carrier_transport プロジェクト(Ricci et al. 2017、CC-BY 4.0)から目的変数を取得(get_transport_data.py:56-71)。/ MP 本体(Materials Project コア DB)はキュレーションされた計算結果、MPContribs は外部研究グループの寄託データ。

mp-id

MP の材料識別子(例: mp-34202)。/ 2 データベースの結合キー(get_transport_data.py:160)。2017 年当時の id が現行 MP に無い場合は結合で脱落する(30,467 → 22,623)。/ 組成式は一意でない(多形)ため、結合キーには使えない。

機械学習側

特徴量

モデルへの入力となる数値変数。本リポジトリでは 145 次元。/ featurize.py が生成、train.py:190 が「メタ・目的変数以外の全列」として選択。/ 「記述子」とほぼ同義だが、記述子は材料を数値化する変換規則側を指すことが多い。

記述子

材料の組成・構造を機械可読な数値に写像する変換とその出力。/ Magpie(組成記述子)+ 構造スカラー(密度等)の 2 系統(featurize.py:4-9)。/ 特徴量の項を参照。

Magpie記述子

元素物性 22 種(原子番号、融点、電気陰性度、価電子数など)について、組成中の元素にわたる 6 統計量(min, max, range, 分率加重 mean, 分率加重 avg_dev, mode)を取った $22 \times 6 = 132$ 次元の組成記述子。数式は 03_featurize.md §3。/ ElementProperty.from_preset("magpie")(featurize.py:45)。/ 構造情報(原子配列)は一切含まない点が構造記述子との差。同一組成の多形は同一の Magpie ベクトルを持つ。

matminer

材料情報学用の Python ライブラリ。記述子生成器を多数提供する。/ StrToComposition と ElementProperty のみ使用(featurize.py:15-16)。/ pymatgen(結晶構造操作)の上位で動くツール群であり、モデル学習は scikit-learn の担当。

one-hotエンコーディング

カテゴリ変数を、カテゴリ数と同数の 0/1 列に展開する変換。/ crystal_system → 7 列(featurize.py:53-54)。/ 整数ラベル化(spacegroup_number の扱い)と異なり、カテゴリ間に偽の順序を持ち込まない。

ランダムフォレスト

ブートストラップ標本で学習した $B$ 本の決定木の平均 $\hat y(x) = \frac{1}{B}\sum_b T_b(x)$ による回帰。/ RandomForestRegressor(n_estimators=300, min_samples_leaf=2)(train.py:138-140)が全 4 モデル共通。/ 勾配ブースティング(XGBoost 等)は木を逐次的に誤差へ適合させる点が異なる。採用理由の比較は 91_design_decisions.md。

train/test分割

データを学習用と評価用に排他分割すること。/ train_test_split(test_size=0.2, random_state=42)(train.py:133-135)で 12,383 / 3,096。/ 行単位の無作為分割であり、材料単位・組成単位のグループ分割ではない(92_audit.md の主要指摘)。

交差検証

データを $k$ 分割し、各分割をテストに回して $k$ 回学習・評価する汎化性能の推定法。5-fold CV の報告値は $\bar R^2 \pm s$(平均と標準偏差)。/ cross_val_score(cv=5) を訓練側 12,383 行のみに適用(train.py:150-151)。/ ホールドアウト(1 回分割)より分散の小さい推定になるが、分割がグループ化されていない点は train/test 分割と同じ。

データリーク

評価時に知り得ないはずの情報が学習・特徴量に混入し、見かけの精度が実力より高くなること。/ 有効質量 $m^*$ の除外(featurize.py:8-9)はターゲット隣接リークの防止。組成重複の分割またぎというリーク経路が残っている(92_audit.md)。/ 過学習(モデルが訓練データに過剰適合すること)とは異なり、リークは評価設計の欠陥である。

GroupShuffleSplit

同一グループ(例: 同一組成)の行が train と test に分かれないよう、グループ単位で無作為分割する scikit-learn の分割器。/ 本リポジトリでは未使用。組成重複への対処として 92_audit.md が導入を検討対象に挙げる。/ train_test_split は行単位、GroupKFold はそのグループ版交差検証。

SHAP

協力ゲーム理論の Shapley 値に基づく寄与分解。予測を $\hat y(x_i) = \phi_0 + \sum_j \phi_{ij}$ と加法分解し、$\phi_{ij}$ が標本 $i$ での特徴量 $j$ の寄与。重要度は $I_j = \mathrm{mean}_i |\phi_{ij}|$。/ shap_analysis(train.py:98-118)。「E_g が S の最重要特徴量」という中心的主張の根拠。/ ランダムフォレスト固有の不純度重要度(feature_importances_)と異なり、標本ごと・方向つきの寄与が得られ、カーディナリティの高い特徴量への偏りも小さい。

TreeExplainer

木系モデルに対し SHAP 値を多項式時間で厳密計算するアルゴリズム。/ shap.TreeExplainer(model)(train.py:101)。テスト集合から 1,000 行を抽出して計算。/ モデル非依存の KernelExplainer は近似かつ低速で、木モデルには通常使わない。

MAE

平均絶対誤差 $\mathrm{MAE} = \frac{1}{n}\sum_i |y_i - \hat y_i|$。目的変数と同じ単位。/ test 評価(train.py:145)。σ モデルでは log₁₀ 空間の値(単位 dex)。/ RMSE と異なり外れ値に線形にしか反応しない。

RMSE

二乗平均平方根誤差 $\mathrm{RMSE} = \sqrt{\frac{1}{n}\sum_i (y_i - \hat y_i)^2}$。/ train.py:146。/ 大きい誤差を二乗で重く数えるため、常に $\mathrm{RMSE} \ge \mathrm{MAE}$。両者の開きは誤差分布の裾の重さの指標になる。

決定係数

$R^2 = 1 - \sum_i (y_i - \hat y_i)^2 / \sum_i (y_i - \bar y)^2$。1 が完全予測、0 が「平均値を返すだけ」と同等。/ test と CV の両方で報告(train.py:147, 150-151)。/ 相関係数の二乗と一致するのは線形回帰の場合のみで、一般のモデルでは負にもなり得る。

パリティプロット

横軸に真値、縦軸に予測値を取り、対角線 $\hat y = y$ からの散らばりで精度を見る散布図。/ parity_plot(train.py:73-95)。横軸ラベルは「DFT+BoltzTraP value」で、真値が計算値であることを明示。/ 残差プロット(横軸真値・縦軸誤差)の変種であり、系統的な過小・過大予測が対角線からの偏りとして見える。

対数変換

目的変数を $\log_{10} y$ に変換して学習すること。/ σ のみ適用(train.py:127-130)。数桁にわたる分布を圧縮し、二乗誤差が大値に支配されるのを防ぐ。/ 逆変換 $10^{\hat y}$ で元の単位に戻せるが、本リポジトリは log₁₀ 空間のまま評価・表示する(MAE の単位 dex)。

目的変数

モデルが予測すべき変数。/ TARGET_COLS の 4 列(featurize.py:24)。/ 「ターゲット」と同義。特徴量(入力)との対をなす。

random_state

擬似乱数の種。/ SEED = 42(train.py:69)を分割・モデル・SHAP 抽出で共有し、再実行の完全再現性を保証する。/ これを固定しても、入力 CSV が MP 側の更新で変われば結果は変わる(再現性の範囲はコードと入力の組に限られる)。

サロゲートモデル

高コストな計算・実験の入出力関係を学習し、低コストで近似する代理モデル。/ 本パイプラインの全モデルは DFT+BoltzTraP のサロゲート(README:5-7)。/ 予測対象が「実験値」ではなく「計算値」である点が、実験データ駆動の物性予測モデルとの差。

設計判断と却下された選択肢

コード・README・docs/DATA_SOURCES.md から読み取れる分岐点を列挙する。「影響」はコードと保存済み成果物から判断できる範囲で書き、再実験しないと分からないものはその旨を明記する。

D1. カスケード禁止(予測値を後段に流さない)

  • 採用: 全ステージの入力をMaterials Project 登録値に固定。バンドギャップ特徴量は band_gap_mp_eV(featurize.py:5-6)、ステージ3 はステージ2 の予測値を使わない(train.py:9-11)。
  • 却下: ステージ1 の予測ギャップを 2・3 の特徴量にする案、ステージ2 の予測 S を 3 の特徴量にする案(README:20-36 が明示的に却下)。
  • 影響: 各モデルが独立に評価可能になり、下流の精度低下の原因切り分けが成立する。代償として「予測しか手に入らない未知材料」への適用時は、登録ギャップの代わりに何かを入れる必要が生じる(現構成ではスクリーニング対象も MP 登録材料である前提)。

D2. 目的変数のデータソース

  • 採用: MPContribs carrier_transport(BoltzTraP 計算値、300 K・$10^{18}\,\mathrm{cm^{-3}}$ 固定、CC-BY 4.0)。
  • 却下: (a) MP 本体 API — 輸送物性が存在しないことを全 69 フィールドの列挙で確認(DATA_SOURCES.md:20-29)。(b) 実験データセット(UCSB/Citrine、ESTM)— mp-id キーでないため登録ギャップ特徴量と E_hull フィルタの設計が崩れる(DATA_SOURCES.md:68-72)。(c) atMax 最適値や温度・濃度分解テーブルの取得 — 1 材料 1 値の設計に合わせて固定条件スカラーを採用(DATA_SOURCES.md:73-75)。
  • 影響: 15,479 件という規模と mp-id 結合の単純さを得た。代わりに目的変数は実験値でなく計算値であり、モデルの検証範囲は「計算の代替」に限定される(README:153-158)。

D3. σ の扱い: 単位換算 + 対数変換

  • 採用: $\sigma = 10 \times (\sigma/\tau)_{\rm raw}$ で S/m に換算(get_transport_data.py:45-47)した上で $\log_{10}\sigma$ を学習(train.py:61-64)。
  • 却下: 線形スケールでの学習(採用しなかった理由はコメント「桁が数桁にわたるため」train.py:61)。$\tau$ を可変にする案はデータ側に存在しない(全材料 $\tau = 10^{-14}$ s 固定)。
  • 影響: 換算は定数倍なので log 空間では切片シフトに過ぎず、R² は換算の有無に依存しない。学習量の実体が $\sigma/\tau$ と等価である点は 92_audit.md A5 参照。

D4. 特徴量の構成

  • 採用: Magpie記述子 132 + MP スカラー 5 + 直接遷移フラグ 1 + 結晶系 one-hot 7 = 145(featurize.py:27-61)。
  • 却下: (a) 有効質量 $m^*$ — 目的変数と同一の BoltzTraP 計算に由来するためデータリークとして除外(featurize.py:8-9)。(b) キャリア濃度 — 全行同値で情報を持たないため除外(DATA_SOURCES.md:89-90)。(c) 結晶構造そのもの(グラフニューラルネット等の構造入力)— コード・文書に検討痕跡なし(採用しなかった理由はコードからは判断不能)。
  • 影響: $m^*$ 除外は見かけ精度の低下と引き換えに評価の健全性を守る選択。組成記述子中心のため、同一組成の多形は 145 次元中 132 次元が同一になり、構造の違いはスカラー 13 次元だけで区別される。

D5. 空間群番号を整数のまま使う

  • 採用: spacegroup_number(1–230)を連続値として投入(featurize.py:32)。
  • 却下: 230 クラスの one-hot(次元爆発)、除外。
  • 影響: 木モデルは整数ラベルを閾値分割で扱えるため線形モデルほど不合理ではないが、番号の大小自体に物理量の意味は無い。S_p で SHAP 4 位に入っており、対称性情報の代理として機能している。

D6. モデル: ランダムフォレスト固定・チューニングなし

  • 採用: RandomForestRegressor(n_estimators=300, min_samples_leaf=2, random_state=42) を 4 ターゲット共通で使用(train.py:138-140)。ハイパーパラメータ探索のコードは無い。
  • 却下: 勾配ブースティング、線形モデル、ニューラルネット、ターゲット別チューニング — いずれも検討痕跡なし(コードからは判断不能)。
  • 影響: スケーリング不要・TreeExplainer で厳密 SHAP が計算できる点は要件(寄与の定量化)に整合する。チューニング不在のため、報告精度は「既定に近い設定の下限」であり、探索で改善する余地の有無は再実験が必要。

D7. 4 モデル独立学習(マルチ出力にしない)

  • 採用: p/n × S/σ の 4 ターゲットを 1 本ずつ独立に学習(train.py:194-197)。
  • 却下: 4 出力同時のマルチターゲット回帰。
  • 影響: ターゲットごとに SHAP・指標が分離され、D1 の「独立に評価可能」という方針と一貫する。ターゲット間相関(S と σ のトレードオフ)は利用されない。

D8. 分割: 行単位の無作為 80/20 + 訓練側 5-fold CV

  • 採用: train_test_split(test_size=0.2, random_state=42) と cross_val_score(cv=5)(train.py:133-135, 150-151)。
  • 却下: GroupShuffleSplit 等の組成グループ分割 — コードに痕跡なし。時系列分割・外挿分割(新規元素系での評価)も無し。
  • 影響: 同一組成の多形が train/test に分かれて入る(テスト行の 27.6%。92_audit.md A1)。報告 R² は「登録済み材料の内挿」の精度であり、未知組成への外挿性能はこれより低い可能性が高い。

D9. 欠損処理: 行削除のみ

  • 採用: 目的変数欠損の行削除(get_transport_data.py:176-177)と特徴量欠損の行削除(featurize.py:66)。
  • 却下: 補完(平均値・モデルベース)。
  • 影響: 現データでは両段とも削除 0 行のため実影響なし。補完と違い分布を歪めないが、将来欠損が増えた場合はサンプル数が黙って減る。

D10. フィルタ基準

  • 採用: $E_{\mathrm{hull}} \le 0.05$ eV/atom(ステージ1 と同一基準、get_transport_data.py:42-43)と MP 登録ギャップ $> 0$(:171)。metal=No フラグ(2017 年判定)だけに頼らない。
  • 却下: E_hull 閾値の別値(0 = 最安定のみ、0.1 等)、BoltzTraP 側のギャップ dE によるフィルタ。
  • 影響: 22,623 → 15,479 件への絞り込み。閾値 0.05 の感度は未検証(再実験が必要)。

D11. キャッシュと再現性

  • 採用: MPContribs 生データを CSV キャッシュ(get_transport_data.py:52-54)、SEED = 42 固定、再生成可能な成果物(.joblib、中間 CSV)は git 管理外(.gitignore:7-10)。

実装監査

検査日 2026-09-15、作業ツリー commit 8a6c36a 基準。件数を伴う指摘は、リポジトリ内の実データ(transport_dataset.csv / features_dataset.csv)に対して random_state=42・test_size=0.2 の分割を再現して計測した値である。

A1. データリーク(同一組成・同一材料の train/test 混入)

指摘あり(組成レベル)。

  • 同一材料の重複は無い: drop_duplicates(subset="material_id")(get_transport_data.py:93)により mp-id は一意で、同じ材料が train と test の両方に入ることはない。
  • 同一組成の重複はある: 15,479 行のうち formula_pretty が重複する行は 4,666 行(1,685 組成)。train.py:133-135 の行単位無作為分割を再現すると、テスト 3,096 行中 856 行(27.6%)は、同じ組成の別行(多形)が訓練側に存在する。
  • 特徴量 145 次元のうち Magpie記述子 132 次元は組成のみから決まるため、これらのペアは特徴量の 9 割超が同一である(スカラー 13 次元は構造依存のため、145 次元が完全一致する train/test ペアは 0 組)。
  • 帰結: 報告されている test R²(0.68–0.76)には「訓練で見たものとほぼ同じ入力の再認」が部分的に含まれ、未知組成に対する汎化性能の推定としては楽観側に偏る。偏りの大きさはグループ分割での再実験(A2)をしないと定量できない。

A2. 分割方法が材料単位になっているか(GroupShuffleSplit 等の要否)

指摘あり(要検討)。 分割は材料(行)単位ではあるが、組成単位ではない(train.py:133-135)。交差検証も同様に行単位である(train.py:150-151)。A1 の混入を断つには GroupShuffleSplit / GroupKFold(groups=formula_pretty)への置き換えが必要。現在のスコアの用途を「MP 登録済み材料の内挿精度」と明示するなら現行分割にも意味はあるが、README:5-7 の掲げる用途(スクリーニング=未知材料への適用)に対しては、グループ分割のスコアを併記しないと過大評価になる。

A3. 前処理が fold 内で閉じているか

該当なし。 本パイプラインの前処理は全て行単位の決定的変換であり、データ分布から統計量を推定する処理(標準化のスケーラ、分位点、PCA 等)が存在しない。Magpie は組成のみの関数(featurize.py:42-47)、one-hot は固定 7 カテゴリの展開(featurize.py:53-54)、対数変換は行ごとの $\log_{10}$(train.py:127-130)である。したがって「テスト集合の統計が前処理を通じて訓練側に漏れる」経路は無い。pd.get_dummies のカテゴリ集合が全データから決まる点も、7 結晶系が固定である限り統計的リークにならない。

A4. 評価指標の妥当性と報告スコアの再現可能性

指標自体は妥当。再現性に条件と注意点あり。

  • 指標の定義(MAE/RMSE/R²、CV は訓練側のみ、train.py:143-153)は正当。テスト集合が CV に混入していない点も確認した。
  • README:82-89 の表の全数値は transport/results/*/metrics.json と一致することを照合済み(例: S_p の MAE 49.4 ↔ 49.4178、CV 0.683±0.033 ↔ 0.6832/0.0327)。
  • SEED=42 固定により、手元の features_dataset.csv からの再実行はビット単位で再現する。ただし features_dataset.csv と carrier_transport_raw.csv は git 管理外(.gitignore:9-10)のため、クローン直後の再構築は現行 MP への問い合わせとなり、MP 側更新で件数・値が変わり得る。README:55-59 の中間件数(22,623・15,682)は実行ログにしか残らず、成果物からは再検証できない。
  • SHAP 順位はテスト集合からの 1,000 行抽出(train.py:100)に基づくため標本ノイズを含む。S の 1 位(2 位に約 4 倍差、shap_importance CSV で確認)は頑健だが、σ の 4 位/7 位は近接順位と入れ替わり得る。
  • 表示側の不整合リスク: app.js:151-190 の KPI「Features 145」「Best R² 0.757」とファネル件数 4 つはハードコードであり、MILAB_RESULTS から転記されない。パリティ PNG も手動コピー運用(2026-09-15 作者確認)。再学習後に更新を怠ってもエラーは出ず、古い数値・図が表示され続ける。
  • 軽微な脆弱性: train.py:162 は importance から band_gap_mp_eV の行を .iloc[0] で取るため、列名が変わると IndexError で落ちる(現状は問題なし)。

A5. 物理的に不整合な仮定(σ/τ 問題を含む)

表記は開示済みで整合。ただし依存文書での明示を推奨。

  • データの実体は $\sigma/\tau$ であり、sigma_p_S_m は $\sigma = (\sigma/\tau)_{\rm raw} \times 10^{15} \times 10^{-14}$(get_transport_data.py:45-47)、すなわち定緩和時間近似 $\tau = 10^{-14}$ s を全材料に一律仮定した換算値である。README:159、index.html:195 はこれを明示しており、「σ/τ を σ と偽装する」不整合には該当しない。
  • ただし $\log_{10}\sigma = \log_{10}(\sigma/\tau)_{\rm raw} + 1$ なので、ステージ3 のモデルが学習している情報は $\sigma/\tau$ と数学的に等価(定数シフト)である。材料間で実際の $\tau$ は桁で異なり得るため、モデルの σ 予測を実測伝導率と比較する用途には使えない。この限定は README には書かれているが、metrics.json・列名にはラベルとして現れない。
  • 特徴量とターゲットの版ずれ: ターゲットは 2017 年の BoltzTraP 計算(当時のバンド構造、band_gap_boltztrap_eV が痕跡)に由来し、特徴量 band_gap_mp_eV は現行 MP の登録値である。両者は同一材料でも一致しない場合があり、ターゲット生成時と異なるギャップ値で学習していることになる。これはリークではなくラベルノイズ側の問題で、精度の上限を下げる方向に働く。設計上どちらを使うかは D1(登録値のみ)で決めた通りであり不整合ではないが、認識しておくべき仮定である。
  • そのほかの物理仮定(GGA ギャップの系統的過小評価、300 K・$10^{18}\,\mathrm{cm^{-3}}$ 固定)はいずれも README・DATA_SOURCES.md に開示済み。S_p 列に負値が存在する(最小 −557 µV/K)のは狭ギャップ材料のバイポーラ伝導で説明でき、不整合ではない。

A6. 単位系の一貫性

該当なし(不整合は発見されなかった)。 検証内容:

  • σ 換算係数 10 の導出: $1/(\mathrm{f\Omega\,m\,s}) = 10^{15}\,\Omega^{-1}\mathrm{m}^{-1}\mathrm{s}^{-1}$、$\times\, \tau\,(10^{-14}\,\mathrm{s}) = \times 10$。コメント(get_transport_data.py:45-46)と実装(:47, :180-181)は一致。
  • E_hull: eV/atom(取得・フィルタ)→ meV/atom(ダッシュボード表示、build_data.py:44 で ×1000、app.js:479 で「meV/atom」表示)。換算・表記とも一貫。
  • S は全経路で µV/K、log₁₀σ の誤差の単位は dex と表記(app.js:60-61, 573)。列名に単位を含める命名(_uV_K、_S_m、_eV、_g_cm3、_A3)が transport_dataset → features → metrics まで維持されている。

A7. その他の実装上の問題

  1. E_hull 欠損の扱いがステージ間で逆: ステージ1 は energy_above_hull is None の行を採用する(get_data.py:63 の条件は None を素通しする)のに対し、ステージ2・3 は notna() を要求して除外する(get_transport_data.py:165)。「同じ基準」(get_transport_data.py:42)という記述は欠損の扱いについては成立していない。実害はステージ1 の 114 行のみ。
  2. キャッシュに無効化機構が無い: carrier_transport_raw.csv が存在する限り、内容がどれだけ古くても黙って再利用される(get_transport_data.py:52-54)。取得条件(フィールド、フィルタ)をコード側で変えた場合、キャッシュを手動削除しない限り反映されない。
  3. CV の fold が連続ブロック: cross_val_score(cv=5) はシャッフル無しの KFold であり、features_dataset.csv は mp-id 順ソート(get_transport_data.py:183)のまま渡される。mp-id 順は登録時期と相関するため、fold 間で材料群の性質が偏る可能性がある。cv_r2_std(0.016–0.033)が小さいことから現データでの実害は小さいと推定されるが、KFold(shuffle=True, random_state=42) の方が意図に忠実。
  4. --fragment の引数検証が無い: sys.argv の直接走査(build_single.py:21-22)のため、--fragment を最後の引数に置くと IndexError になる。実害は限定的。

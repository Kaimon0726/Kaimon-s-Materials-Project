# 07 — web/app.js(ダッシュボード本体。付: index.html / style.css)

### 0. 図中の対応箇所

元の図に対応ノードが無い([00_verify.md](00_verify.md) の欠落 4)。修正版 mermaid の `web/index.html + style.css + app.js(手書き。非バンドル版としてそのまま動作)` ノードに対応する。作者回答(2026-09-15)により、この非バンドル版が配布の正である。

### 1. このファイルの役割

依存ライブラリ無しの単一 JS(655 行)で、3 ビュー(概要 / エクスプローラー / モデル評価)の SPA を実装する。`build_data.py` が書き出したグローバル `MILAB_DATA`(15,479 行)と `MILAB_RESULTS`(指標・SHAP)を読み、散布図・表・KPI・SHAP バーを描画する。`index.html` は静的な骨格(215 行)、`style.css` はテーマ変数と装飾(557 行)で、いずれも関数を持たない。

### 2. 入力と出力

**入力**: `window.MILAB_DATA`(行配列。列位置は定数 `C` で参照、20-24 行)、`window.MILAB_RESULTS`、任意で `window.MILAB_PARITY`(バンドル版のみ)、パリティ PNG(分離版は `assets/` 相対パス、57-61 行)、URL ハッシュ(`#overview` 等)。**出力**: DOM と Canvas 2D への描画のみ。ファイル・ネットワーク・ストレージへの書き込みは無い(外部リンクは MP の材料ページのみ、491 行)。

### 3. 関数ごとの解説

数値計算を含む関数を主に説明する。純粋な DOM 組み立て(`renderOverview`、`initControls`、`renderTooltip`、`renderDetail`、`renderTable`、`initModels`、`renderModels`)は、状態 `state`(105-117 行)を読み、`el()` で要素を構築して差し替えるという同型の処理である。

**`rampBins(key)`**(132-143 行): 散布図の点の濃さ(6 段)を決める等頻度ビンを作る。対象列の全値をソートし、分位点関数を $Q(q) = \mathrm{vals}[\lfloor N q \rfloor]$ として、内部境界を

$$e_i = Q\!\left(\frac{i}{6}\right),\quad i = 1, \dots, 5$$

で取る。各ビンに全体の 1/6 ずつが入る。凡例の端は $Q(0.005)$ と $Q(0.995)$ で外れ値の影響を避ける。等幅ビンではなく等頻度にしている理由はコメント(127-131 行)にある通り、log₁₀σ などの分布が最頻値付近に集中しており、等幅では大半の点が 1 色に潰れるためである。ビンは**全 15,479 行**で計算し、フィルタ後の部分集合では再計算しない(フィルタ操作で生存点の色が変わらないようにするため)。`binCache` により列ごとに 1 回だけ計算する。

**`rampIndex(v, bins)`**(144-148 行): 値 $v$ に対しビン番号 $\min\{i : v < e_i\}$(どの境界も超えれば 5)を返す線形探索。

**`niceTicks(min, max, n=6)`**(91-101 行): 軸目盛りの選択。生の刻み $s_0 = (\max - \min)/n$ に対し、$10^{\lfloor \log_{10} s_0 \rfloor}$ の {1, 2, 2.5, 5, 10} 倍のうち目盛り数が $n$ 以下になる最小の刻み $s$ を選び、$\lceil \min/s \rceil s$ から $s$ 刻みで並べる。

**`drawScatter()`**(288-388 行): Canvas への散布図描画。デバイスピクセル比でキャンバスを拡大してから、データ座標 $(v_x, v_y)$ を画素座標へ写すアフィン変換

$$s_x(v) = \mathrm{pad}_l + \frac{v - x_{\min}}{x_{\max} - x_{\min}} \cdot iw,\qquad s_y(v) = \mathrm{pad}_t + \left(1 - \frac{v - y_{\min}}{y_{\max} - y_{\min}}\right) \cdot ih$$

で全点を打つ($iw, ih$ は描画領域の幅・高さ。$y$ は画面座標が下向きのため反転)。軸範囲はフィルタ後の点の min/max に 3–5% の余白を足したもの。点は色ビンごとにまとめて描き、濃い側を後に描いて上に載せる(363-374 行)。点数 4,000 超で不透明度を 0.72 → 0.42 に落とす(366 行)。計算量は表示点数 $O(N)$。

**`nearestRow(mx, my)`**(396-406 行): ホバー・クリック対象の探索。全表示点との二乗距離 $d^2 = (s_x - m_x)^2 + (s_y - m_y)^2$ を線形走査し、$d^2 < 24^2$ 画素以内で最小の点を返す。空間インデックスは使っておらず 1 回の走査は $O(N)$ だが、$N \le 15{,}479$ では実用上問題ない。

**`filteredRows()`**(119-125 行): [[結晶系]]フィルタ(`state.systems` の集合帰属)と検索文字列(組成式または [[mp-id]] の部分一致、小文字化)の論理積。

**`renderModels()`**(566-625 行): 選択ターゲットの指標([[MAE]]・[[RMSE]]・[[決定係数]]・[[交差検証]] R²・E_g の [[SHAP]] 順位)を KPI タイルに、SHAP 上位 15 件をバー(幅 $\propto I_j / I_1$、605 行)に描く。パリティ画像は `MILAB_PARITY`(バンドル版)→ `assets/` 相対パス(分離版)の順でフォールバックする(620-622 行)。

**`route()` / `boot()`**(6-16, 640-655 行): ハッシュでビューを切り替え、起動時にデータ欠如を検出してガイダンスを表示する。`ResizeObserver` でリサイズ時に再描画。

### 4. なぜこの処理が必要か

**物理側**: 新しい計算は無い。等頻度ビンと log₁₀ 軸は、桁で分布する物性値を視覚的に読み取り可能にするための表示変換である。

**機械学習側**: 学習結果の検証経路として機能する。散布図で $E_g$ と S の関係(小ギャップで S が抑制される[[バイポーラ伝導]]傾向)を全数データで直接確認でき、SHAP バーとパリティ図はモデルの主張(E_g 1 位、R² の水準)を成果物から転記して見せる。

### 5. この処理を外したらどうなるか

パイプラインの学習・評価(metrics.json まで)は無傷で残る。失われるのは可視化と対話的検証のみで、逆依存は `build_single.py` が app.js を読む 1 箇所(26 行)だけである(app.js が無ければバンドルも失敗する)。注意点として、`renderOverview`(151-190 行)の KPI「Features 145」「Best R² 0.757」と絞り込みファネルの 4 つの件数(30,467 / 22,623 / 15,682 / 15,479)は **`MILAB_RESULTS` からの転記ではなくハードコード**であり、再学習で数値が変われば手動更新しない限り古い値を表示し続ける([92_audit.md](92_audit.md) 参照)。

# mi-project コード解説(初学者向け)

> **目的**: このリポジトリの中で「どのファイルが何を受け取り、何をして、何を吐き、なぜ必要か」を
> 自分の言葉で説明できるようになること(大学院面接対策)。
>
> **表記のルール**: 根拠はすべて `ファイル名:行番号` または関数名で示します(行番号は
> 2026-08-27 時点の作業ツリー基準)。「**推測**」と明記した箇所以外は、コードやデータを
> 直接確認した事実だけを書いています。

---

## 0. このリポジトリをひと言でいうと

**「スーパーコンピュータで何時間もかかる物性計算(第一原理計算)を、過去の計算結果
15,479 件から学習した機械学習モデルで一瞬で代替する」** プロジェクトです。

- 予測する物性は 2 つ: **ゼーベック係数 S**(温度差を電圧に変える能力。熱電材料の性能指標)と
  **電気伝導率 σ**(電気の流れやすさ)。それぞれ p 型 / n 型の 2 通りで、計 4 つのモデルを作ります。
- 材料データはすべて [Materials Project](https://materialsproject.org/)(略称 MP。世界最大級の
  計算物性データベース)とその付属データベース MPContribs から取得します。
- 最大の設計上のこだわりは **「カスケード禁止」**: 前の段階のモデルの予測値を、次の段階の
  入力に使わない(理由は §2.2 の README 解説と §5 Q1 参照)。

ステージ構成(README.md:9-13):

| ステージ | 予測対象 | 位置づけ |
|---|---|---|
| 1 | バンドギャップ | 導入デモ。**このリポジトリにあるのはデータ取得のみ**(後述) |
| 2 | ゼーベック係数 S | 本体。15,479 材料で学習 |
| 3 | 電気伝導率 σ | 本体。同じデータで独立に学習(※現在「使わない方針」— §3.2 参照) |

## 1. データフローの全体図

「どのファイルがどのファイルを生成するか」を上から下へ並べた図です。
`──▶` の左が生成する側(スクリプト)、右が生成される側(データ)です。

```
[.env]  MP_API_KEY(Materials Project の API キー。全取得スクリプトが読む)
   │
   ├── ステージ1(独立した導入デモ。以降のパイプラインとは接続していない)
   │
   │   get_data.py ──▶ semiconductor_band_gaps.csv (114行)
   │                    ※現在、これを読むコードはリポジトリに存在しない(§3.1)
   │
   └── ステージ2・3(本体パイプライン)
       │
       transport/get_transport_data.py
       │   ├─(中間キャッシュ)──▶ transport/data/carrier_transport_raw.csv (30,467行×7列)
       │   └─(MP と結合・絞り込み)▶ transport/data/transport_dataset.csv (15,479行×19列)
       │
       transport/featurize.py
       │   └─────────────────────▶ transport/data/features_dataset.csv (15,479行×151列)
       │
       transport/train.py --stage 2 / --stage 3
       │   └──▶ transport/results/stage2_seebeck/      ┐ metrics.json(精度指標)
       │        transport/results/stage3_conductivity/ ┘ model_*.joblib(学習済みモデル)
       │                                                  parity_*.png(予測vs正解の図)
       │                                                  shap_summary_*.png / shap_importance_*.csv
       │                                                  (どの特徴量が効いたかの分析)
       ├───────────────────────────────────────────────────────────┐
       web/build_data.py                                            │
       │   └──▶ web/data/dataset.js + web/data/results.js           │
       │        (CSV と metrics.json を、ブラウザが読める JS 形式に変換)│
       │                                                            │
       │   web/index.html + web/style.css + web/app.js(手書きの画面。生成物ではない)
       │   web/assets/parity_*.png(results/ の図のコピー ※コピー処理はリポジトリに無い→§3.3)
       │                                                            │
       web/build_single.py(上記すべてを 1 ファイルに合体)◀───────────┘
           └──▶ web/dist/milab-dashboard.html(配布用の全部入り1ファイル)
```

実行順(README.md:140-150 の再現手順と同じ):

| 順 | コマンド | 読むもの | 作るもの |
|---|---|---|---|
| 1 | `python transport/get_transport_data.py` | .env、(2つのAPI) | carrier_transport_raw.csv、transport_dataset.csv |
| 2 | `python transport/featurize.py` | transport_dataset.csv | features_dataset.csv |
| 3 | `python transport/train.py --stage 2` | features_dataset.csv | results/stage2_seebeck/ 一式 |
| 4 | `python transport/train.py --stage 3` | features_dataset.csv | results/stage3_conductivity/ 一式 |
| 5 | `python web/build_data.py` | transport_dataset.csv、metrics.json、shap_importance_*.csv | web/data/dataset.js、results.js |
| 6 | `python web/build_single.py` | web/ 内のほぼ全部 | web/dist/milab-dashboard.html |

ポイント: **前のステップの出力が次のステップの入力**という一方向の流れで、
逆流や横道はありません。`get_data.py` だけがこの流れに参加していない独立ファイルです。

#### `get_data.py` — ステージ1: バンドギャップのデータ取得

| | |
|---|---|
| 入力 | .env の API キーと、コード内に直接書かれた 8 つの組成式 `["Si", "Ge", "GaAs", "GaN", "ZnO", "InP", "CdTe", "ZnS"]`(get_data.py:20) |
| 処理 | 組成式ごとに Materials Project を検索し(関数 `fetch_band_gap_data`、get_data.py:44-56)、不安定な構造(E_hull > 0.05 eV/atom)を捨て(get_data.py:63-65)、バンドギャップ・結晶の形・体積などを表に集める |
| 出力 | `semiconductor_band_gaps.csv`(get_data.py:103-104)。8 組成で 114 行になるのは、同じ組成でも原子の並び方が違う「多形」が複数登録されているため(例: CdTe だけで立方晶と六方晶がある) |
| なぜ必要か | 「データベースから物性データを取ってきて表にする」という全工程の最小デモ。E_hull ≤ 0.05 という安定相フィルタはここで決まり、ステージ2・3でも同じ基準を使う(get_transport_data.py:42-43 のコメントが明言)。**ただし現在、この出力 CSV を読むコードは無い**(§3.1) |

注意: このリポジトリに**ステージ1の「学習」コードはありません**。README.md:107 も
`Stage 1: band-gap data acquisition (intro demo)`(データ取得)とだけ書いています。
面接で「ステージ1のモデルは?」と聞かれたら「ステージ1はデータ取得と可視化のデモで、
学習はステージ2・3で行う構成」と答えるのが実態に即しています。

#### `README.md`

プロジェクトの顔。特に大事なのは:

- **カスケード禁止の理由**(README.md:29-36): 前段の予測値を後段に入れると、前段の間違いが
  後段に伝染し、後段の精度が悪いとき「モデルが悪いのか、もらった入力が悪いのか」を
  切り分けられなくなる。だから各ステージの入力は必ず**データベース登録値**にする。
- **データの絞り込みの数字**(README.md:55-59): 30,467 → 22,623 → 15,682 → **15,479** 件。
- **結果の一覧表**(README.md:82-97): 各モデルの精度と「バンドギャップが特徴量重要度 1 位」という発見。

#### `docs/DATA_SOURCES.md`

実装の**前に**行ったデータソース調査の記録(2026年7月、実際に API を叩いて検証済みと
明記されている: DATA_SOURCES.md:3-6)。

- MP 本体の API には輸送物性(S や σ)が**一切無い**ことを全 69 フィールドの列挙で確認
  (DATA_SOURCES.md:20-29)→ だから別のデータベース(MPContribs)が必要になった。
- 採用した `carrier_transport` データセットの素性(Ricci らの 2017 年論文、CC-BY 4.0
  ライセンス、47,737 件中 30,467 件が非金属: DATA_SOURCES.md:34-47)。
- **§4 の「温度・ドーピング濃度」問題の答えの根拠もここにある**(DATA_SOURCES.md:54-56)。

#### `semiconductor_band_gaps.csv`

`get_data.py` の出力(上記)。列は material_id、組成式、バンドギャップ、直接/間接遷移、
結晶系、空間群、体積、原子数、E_hull の 9 列。**§3.1 の通り、現在どのコードからも
読まれていません。**

### 2.2 `transport/` — パイプライン本体

#### `transport/get_transport_data.py` — ステージ2・3のデータセット構築

このリポジトリで一番重要なスクリプト。**2 つのデータベースを「材料ID(mp-id)」で
突き合わせて 1 つの表にする**のが仕事です。

| | |
|---|---|
| 入力 | ① MPContribs `carrier_transport`(答え側: S と σ の計算値)② MP 本体 summary API(特徴量側: 登録バンドギャップ・密度など)。ローカルにキャッシュがあれば ① は API を叩かずキャッシュを読む(get_transport_data.py:52-54) |
| 処理 | 下の 5 ステップ |
| 出力 | `data/carrier_transport_raw.csv`(①の生キャッシュ、30,467 行)と `data/transport_dataset.csv`(結合・選別済み 15,479 行 × 19 列) |
| なぜ必要か | 答え(S, σ)と手がかり(バンドギャップ等)は**別々のデータベース**にあるので、繋がないと学習データにならない。また玉石混交の 3 万件から「安定で、半導体で、値が揃っている」ものだけを選ばないと、学習がノイズだらけになる |

処理の 5 ステップ(`main`、get_transport_data.py:153-197):

1. **輸送物性の全件取得**(関数 `fetch_carrier_transport`、:50-97)
   MPContribs に「metal = No(非金属)のものを全部」と問い合わせる(:59-71。
   `data__metal__exact: "No"` が :60)。1 材料 = 1 行、7 列で保存(:83-91)。→ 30,467 件
2. **MP 本体との結合**(関数 `fetch_mp_summary` :100-150 + merge :160)
   mp-id を 1,000 件ずつに分けて MP に照合(:109-111。一度に全部送ると API の上限を超えるため)。
   2017 年当時の ID が今の MP に無いものはここで落ちる。→ 22,623 件
3. **安定相フィルタ**(:165-166): E_hull ≤ 0.05 eV/atom だけ残す。→ 15,682 件
   (E_hull =「その組成の一番安定な構造とのエネルギー差」。小さいほど実在・合成しやすい)
4. **半導体フィルタ**(:171): MP 登録バンドギャップ > 0 だけ残す。→ 15,479 件
5. **仕上げ**(:176-181): 4 つの答え(S の p/n、σ の p/n)のどれかが欠けた行を捨て
   (:176-177。実際には生データに欠損ゼロなので 1 行も減らない — §3.2 で検証)、
   σ を物理単位 S/m に換算した列を追加(:180-181。換算係数 ×10 の意味は :45-47 のコメント)。

最後に Bi₂Te₃ など有名な熱電材料が生き残っているか自動チェックして表示します(:188-197)。
「絞り込みすぎて本命の材料まで消えていないか」の健全性確認です。

#### `transport/data/carrier_transport_raw.csv`(git 管理外)

| | |
|---|---|
| 入力/出力 | `fetch_carrier_transport` が書き(:95)、次回実行時に読む(:52-54) |
| 中身 | 30,467 行 × 7 列: material_id、組成式、BoltzTraP計算時のバンドギャップ(参考値)、S の p/n、σ/τ の p/n。**温度・ドーピング濃度の列は無い**(§4) |
| なぜ必要か | API 取得は数分かかるので、2 回目以降のためのキャッシュ。消しても再実行すれば復元される |

#### `transport/data/transport_dataset.csv`

パイプラインの「一次完成品」。15,479 行 × 19 列(答え 4 列 + MP 由来の特徴量の素材 + ID類)。
これ以降は API を叩かず、このファイルだけから全てが作られます。web 側もこれを直接読みます
(web/build_data.py:17)。

#### `transport/featurize.py` — 特徴量(モデルへの入力)づくり

| | |
|---|---|
| 入力 | transport_dataset.csv(featurize.py:19, 37) |
| 処理 | 組成式(例 "Bi2Te3")を、機械学習が扱える**数値の列 145 個**に変換する。内訳: ① matminer ライブラリの「Magpie」プリセットで、構成元素の性質(原子番号・電気陰性度・融点など)の統計量 132 個(:42-46)② MP 登録値のスカラー 5 個 — バンドギャップ・密度・原子あたり体積・原子数・空間群番号(:27-33)③ 直接/間接遷移フラグを 0/1 に(:50)④ 結晶系 7 種を 0/1 の 7 列に展開(one-hot、:53-54)。欠損のある行を捨てて保存(:63-69。実際は 1 行も減らない — 行数一致を確認済み) |
| 出力 | features_dataset.csv(15,479 行 × 151 列 = ID 2 + 答え 4 + 特徴量 145) |
| なぜ必要か | モデルは文字列("Bi2Te3")を食べられない。また「どの数値を入力に選ぶか」はこのプロジェクトの主張そのもの: バンドギャップは **MP 登録値**を使う(:5 のコメント、列名 `band_gap_mp_eV` :28)、答えと同じ計算から出てきた有効質量 m* は**カンニングになるので入れない**(:8-9 のコメント。§5 Q2) |

#### `transport/train.py` — 学習と評価(ステージ2・3共通)

| | |
|---|---|
| 入力 | features_dataset.csv(train.py:39, 189)と、コマンドラインの `--stage 2` / `--stage 3`(:181-183) |
| 処理 | 下の流れを、指定ステージの p 型・n 型それぞれに実行(1 回の実行で 2 モデル) |
| 出力 | `results/stage2_seebeck/` または `results/stage3_conductivity/` に、モデル・精度指標・図・重要度ランキング(:15-21 のコメントに一覧) |
| なぜ必要か | ここが「機械学習」本体。これが無いと、集めたデータはただの表で終わる |

`train_one_target`(:121-177)の流れ:

1. **σ だけ log₁₀ に変換**(:125-128)。σ は材料によって何桁も違うので、そのまま学習すると
   大きい値ばかり合わせにいく。桁(指数)を当てる問題に直す(設定は STAGE_CONFIG :58-66)。
2. **8:2 に分割**(:133-135)。8 割で学習し、**見せていない 2 割**で実力テストをする。
   分割の乱数は固定(SEED=42、:69)なので誰がやっても同じ結果になる。
3. **ランダムフォレスト回帰で学習**(:138-141)。決定木(if-then の連続で答えを出す木)を
   300 本作って多数決させる方式。
4. **採点**(:144-153): テスト 2 割に対する MAE(平均でどれだけ外すか)・RMSE・R²(1 に
   近いほど良い)と、学習データを 5 分割して回す交差検証 R²(まぐれでない安定性の確認)。
5. **成果物の保存**(:156-159): パリティプロット(横軸=正解、縦軸=予測。対角線に乗るほど
   正確。関数 `parity_plot` :73-95)、SHAP 分析(どの特徴量がどれだけ予測に効いたかを
   数値化。関数 `shap_analysis` :98-118)、学習済みモデル。
6. **バンドギャップの順位を表示**(:161-163): このプロジェクトの主張「ギャップが輸送物性を
   駆動する」を数字で確かめる 1 行。結果はゼーベック係数で **145 特徴量中 1 位**
   (results/stage2_seebeck/metrics.json の `band_gap_shap_rank`)。

|---|---|

| model_*.joblib | 学習済みモデル本体(git 管理外、約45MB。:159 が書く) |

## 4. 温度とドーピング濃度は「どこで絞られた」のか

**結論: コードのどこでも絞り込んでいません。「300 K・キャリア濃度 10¹⁸ cm⁻³ の値だけが
入っているデータ欄」を取得時に選んでいるので、温度や濃度の列は最初から存在しないのです。**

順を追って:

1. Ricci らの元データベース自体は、温度 100–1300 K × キャリア濃度 10¹⁶–10²¹ cm⁻³ の
   **格子(グリッド)全体**の計算値を持っています。ただし MPContribs 上の要約フィールド
   (`data.S.p.value` など)は、その中から **300 K・10¹⁸ cm⁻³ の 1 点**を代表値として
   収めたものです。これは実装前の調査で確認・記録されています(docs/DATA_SOURCES.md:54-56。
   「All scalar values are ... at fixed conditions: T = 300 K, carrier concentration 10¹⁸ cm⁻³」)。
2. 取得コードは、その要約フィールド**だけ**を API に要求しています。該当箇所は
   `fetch_carrier_transport` 内のフィールド指定 **transport/get_transport_data.py:61-69**
   (:65 のコメントに `@300K, 1e18 cm^-3` と明記。ファイル冒頭 :6 にも同じ説明)。
   つまり「1 材料 = 1 行」の形でしかデータが届かず、行を温度で選ぶ工程がそもそも無い。
3. その結果、生データ carrier_transport_raw.csv の列は
   `material_id, formula_ricci, band_gap_boltztrap_eV, seebeck_p_uV_K, seebeck_n_uV_K,
   sigma_over_tau_p, sigma_over_tau_n` の 7 列のみ(実ファイルのヘッダで確認済み。
   書き込み側のコードは get_transport_data.py:83-91)。**温度・濃度の列は生データの
   時点で存在しません**。transport_dataset.csv に無いのはその引き継ぎです。
4. 温度・濃度ごとの最適値(`atMax` フィールド)を取る選択肢は調査段階で検討され、
   「固定条件のスカラーの方が、1 材料 1 値というステージ1 以来の設計に合う最も素直な
   回帰ターゲットだ」という理由で**意図的に不採用**になりました(DATA_SOURCES.md:73-75)。
5. 同じ理由の続きで、「キャリア濃度は全行 10¹⁸ cm⁻³ で共通=材料ごとの違いを何も
   語らないので特徴量にもしない」と決めています(DATA_SOURCES.md:89-90、README.md:72-73)。
6. この条件はダッシュボードにも明示されています: 散布図の件数表示の隣に
   「300 K · n = 10¹⁸ cm⁻³」と常時表示(web/app.js:308-309)。

面接での一言回答例:
「温度とドーピング濃度でフィルタしたのではなく、データベース側が提供する
300 K・10¹⁸ cm⁻³ 固定の代表値フィールドを回帰ターゲットに選びました。全行で条件が
共通なので、列として持つ意味がなく、特徴量にも入れていません。温度依存性の予測は
今後の拡張課題です。」

## 6. ミニ用語集

| 用語 | ざっくり言うと |
|---|---|
| バンドギャップ (E_g) | 電子が「動ける状態」になるために飛び越えるエネルギーの隙間。0 なら金属、大きいと絶縁体 |
| ゼーベック係数 (S) | 材料の両端に温度差をつけたとき生じる電圧の大きさ。熱電発電の性能の心臓部 |
| 電気伝導率 (σ) | 電気の流れやすさ。本データでは緩和時間 τ を 10⁻¹⁴ s と仮定した換算値 |
| p 型 / n 型 | 不純物添加(ドーピング)で、プラスの担い手(正孔)/マイナスの担い手(電子)を増やした半導体 |
| DFT(第一原理計算) | 量子力学の方程式を近似的に解いて、実験なしで材料の性質を計算する手法。高精度だが高コスト |
| BoltzTraP | DFT の結果から S や σ などの「輸送物性」を計算する定番プログラム |
| Materials Project (MP) | DFT 計算結果を 15 万件以上集めた公開データベース。材料ごとに mp-○○ という ID が付く |
| MPContribs | MP 本体に載らない外部研究データを、同じ mp-id で紐づけて公開する併設データベース |
| E_hull (energy above hull) | 同じ組成の最安定構造とのエネルギー差。0 に近いほど「実在しやすい」 |
| Magpie / matminer | 組成式から元素物性の統計量(平均電気陰性度など)を自動生成する特徴量ライブラリ |
| ランダムフォレスト回帰 | 「if-then の木」を数百本作って平均を取る予測モデル。表データに強い定番 |
| 訓練/テスト分割・交差検証 | 学習に見せなかったデータで採点する仕組み。丸暗記(過学習)を見抜くため |
| MAE / RMSE / R² | 平均誤差 / 大外れに敏感な誤差 / 当てはまりの良さ(1 が満点) |
| SHAP | 1 つ 1 つの予測について「どの特徴量が何点分押し上げ/押し下げたか」を配分する説明手法 |
| パリティプロット | 横軸=正解、縦軸=予測の散布図。対角線に乗るほど正確 |
| (データ)リーク | 答えそのもの・答えの親戚を入力に混ぜてしまい、実力以上の精度が出てしまう事故 |
